## 주요 기능

### 떠오르는 순간, 잊기 전에 기록

내용만 적고 Enter를 누르면 저장됩니다. 카테고리와 중요도도 초기 입력 영역에서 바로 선택할 수 있어, 기록과 정리를 한 번에 마칠 수 있습니다.

- PC에서는 Shift + Enter로 줄바꿈하고, 엔터를 누르면 메모가 바로 저장됩니다.
- 카테고리 페이지 안에서 메모를 작성하면 기본적으로 해당 카테고리의 메모로 들어갑니다.
- 짧은 메모부터 추가 설명, 날짜 및 반복 등 추가 설정이 필요한 기록까지, 필요한 만큼 작성할 수 있습니다. 일단 가볍게 메모하고, 추후 자세한 내용을 수정해 보세요!

### 오늘의 시작은, 지금 챙길 기억부터

홈에서 **지금 챙길 기억**과 **최근 남긴 기억**을 함께 확인하세요. 기한이 지났거나 시간이 임박한 일, 오늘 할 일과 중요한 메모를 먼저 살펴볼 수 있습니다.

- 최상부터 최하까지 5단계 중요도로 우선순위를 구분합니다.
- 오늘 탭에서 오늘 일정, 기한이 지난 미완료 항목, 오늘의 루틴(반복) 할 일을 확인합니다.
- 목록에서는 메모의 작성일자만 표시되고, 메모 상세보기 하단에 최초 작성일시와 수정일시가 각각 표시됩니다.

### 내 생각의 순서대로 정리

회사, 공부, 일상처럼 큰 주제로 묶고, 하위 카테고리로 더 세밀하게 나누세요. 분류도 순서도 내 방식에 맞출 수 있습니다.

- 카테고리와 하위 카테고리 생성·편집·이동, 접기·펼치기
- 드래그로 카테고리 순서와 계층 변경, 커스텀 정렬에서 메모 순서 변경
- 모바일에서는 길게 눌러 드래그
- 내용 검색과 카테고리 필터, 중요도순·최신순 정렬
- 완료한 일은 기본 목록에서 숨기고, 완료 화면에서 확인하거나 되돌리기

### 한 번의 약속도, 매일의 습관도

점심 약속에는 날짜와 시간을, 프로젝트에는 시작일과 종료일을, 운동에는 반복 요일을 설정하세요.

- 날짜·시간 또는 기간으로 일정 지정
- 매일 반복과 선택한 요일 반복
- 반복 할 일은 날짜별로 완료를 기록하고 다음 예정일에 다시 표시
- 놓친 반복 할 일이 날짜별로 계속 쌓이지 않도록 처리

### 책상 앞에서도, 이동 중에도 이어서

Google 계정으로 로그인하면 같은 계정의 기록을 PC와 모바일에서 이어서 사용할 수 있습니다.

- 넓은 화면에서는 목록과 상세 편집 패널을 함께 표시
- 모바일에서는 터치에 맞춘 메뉴와 상세 패널, 오른쪽으로 밀어 닫기 지원
- 저장하지 않은 수정 내용이 있으면 닫기 전에 확인
- 지원하는 Android 브라우저에서 홈 화면에 설치해 앱처럼 실행

### 쌓아 둔 기억을, 내 손에

기록을 파일이나 텍스트로 보관하고 다시 가져올 수 있습니다. 예시로 체험하기는 실제 기록과 분리되어 있어 부담 없이 기능을 살펴볼 수 있습니다.

- JSON 텍스트 복사 또는 백업 파일로 저장하기
- JSON 붙여넣기 또는 백업 파일 불러오기
- 백업 형식을 검증하고, 기존 기록을 대체하기 전에 확인하기

## 사용 경험을 위한 설계

**기록까지의 단계를 줄였습니다.** 입력과 분류를 한 영역에 모으고, 일정과 반복은 필요할 때 펼칩니다. 짧은 생각 하나를 남기기 위해 모든 항목을 채울 필요가 없습니다.

**다시 열었을 때의 흐름도 챙겼습니다.** 로그인 계정을 확인한 뒤 유효한 로컬 사본이 있으면 먼저 보여주고 서버 데이터로 갱신합니다. 사본을 보여주는 동안에는 읽기 전용으로 유지해 서버 확인 전 수정 충돌을 방지합니다.

**화면 크기에 맞춰 조작 방식을 바꿨습니다.** PC에서는 넓은 편집 공간과 키보드 입력을, 모바일에서는 터치 드래그와 스와이프를 지원합니다. 모바일 패널 전환을 다듬고 상세 패널을 스크롤할 때 뒤의 목록이 함께 움직이지 않도록 처리했습니다.

## 데이터 저장과 이용 범위

- 기록은 Firebase Firestore에 계정별로 저장하며, 접근 권한은 Firebase Authentication과 Firestore 보안 규칙으로 제어합니다.
- 첫 화면의 빠른 로딩용 데이터를 암호화해 저장합니다. 키는 Web Crypto의 추출 불가능한 키로 보관하며, 사본과 키는 생성 후 24시간이 지나거나 로그아웃하면 삭제합니다.
- 서버 동기화에는 인터넷 연결이 필요합니다. 전체 오프라인 사용과 앱을 닫았을 때의 알림은 지원하지 않습니다.
- Android 설치는 브라우저의 PWA 설치 기능을 사용하며, Play Store에 등록된 네이티브 앱은 아닙니다.

## 로컬 실행

Node.js 22.13 이상과 pnpm 11.25.0을 사용합니다.

```sh
git clone https://github.com/pabu-lim/gieokham.git
cd gieokham
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

개발 서버가 표시하는 주소를 엽니다(기본 포트 5173).
Google 로그인 개발 테스트에는 Firebase Authentication의 승인된 도메인에 `localhost`를 등록해야 합니다.

```sh
pnpm exec tsc --noEmit --incremental false
pnpm build
pnpm start
```

`pnpm start`는 빌드한 Worker의 로컬 미리보기입니다. 배포 명령이 아닙니다.

## Firebase

현재 앱은 기존 `girokham-1` 프로젝트를 사용합니다. 앱 이름을 기억함으로 바꿨지만 데이터 연속성을 위해 Firebase 프로젝트 ID는 유지합니다.
웹 클라이언트 설정은 `lib/firebase.ts`에 있습니다. 다른 Firebase 프로젝트로 복제한다면 이 설정을 해당 프로젝트의 웹 앱 설정으로 교체하세요.

- Authentication: Google 로그인 활성화, 사용하는 호스트 이름을 승인된 도메인에 추가
- Cloud Firestore: `users/{uid}/app/state` 문서에 사용자 상태 저장
- 접근 제어: 로그인한 사용자만 자신의 경로에 접근할 수 있도록 Firestore 규칙 설정

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

위 규칙은 운영 콘솔의 현재 설정을 자동으로 변경하지 않습니다. Firebase 웹 설정은 브라우저에 공개되는 클라이언트 식별 정보이며, 데이터 접근 권한은 Authentication과 Firestore 규칙으로 제어합니다. 서비스 계정 키나 관리자 인증 정보는 저장소에 넣지 마세요.

## 배포 상태

이 저장소는 현재 서비스의 소스 스냅샷입니다. GitHub의 코드를 변경하는 것만으로 기존 Sites 서비스가 자동 업데이트되지는 않습니다.

현재 빌드는 React + Vinext/Vite와 Cloudflare Worker 구조입니다. `dist/client`와 `dist/server`를 생성하므로 GitHub Pages에 소스만 올리는 방식으로는 실행되지 않습니다.
외부 호스팅으로 이전하려면 호스팅 연결과 배포 파이프라인을 별도로 설정해야 합니다. 새 주소를 정한 뒤 Firebase의 승인된 도메인에도 추가하세요.
